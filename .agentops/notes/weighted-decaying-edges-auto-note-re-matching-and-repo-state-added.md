---
title: "weighted decaying edges, auto note re-matching, and repo state added"
type: decision
---

Extended the graph with three additions inspired by an old fiction-writing memory-architecture doc that turned out to be Codebrain's own conceptual origin: (1) Affects edges now carry a weight (default 1.0, +0.5 per reinforcement, capped at 5.0) that decays via effective_weight's 30-day half-life at read time, computed identically on SQLite and Postgres in Rust rather than diverging per-backend; (2) persist() now auto re-matches existing notes against current symbols on every scan, closing the previously-documented notes-written-before-first-scan-never-attach-to-symbols gotcha for good instead of requiring a manual ingest-notes step; (3) a new repo_state table gives a fast top-5-gotchas/decisions snapshot, refreshed at the same scan hook, deliberately kept separate from bi-temporal node-content versioning rather than competing with it. Migrated agentops-graph's SQLite schema onto rusqlite_migration (found via context7, replacing a hand-rolled column-existence check) since the project previously had no real ALTER-TABLE-capable migration framework at all. Live-verified against this repo's own real, already-populated graph.db: 112 pre-existing edges survived the migration intact, and the 31 pre-existing Affects edges were reinforced (1.0 to 1.5 to 2.0) across two real installs.
