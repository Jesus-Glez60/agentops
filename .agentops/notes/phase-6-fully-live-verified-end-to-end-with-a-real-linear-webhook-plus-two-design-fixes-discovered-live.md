title: "Phase 6 fully live-verified end-to-end with a real Linear webhook, plus two design fixes discovered live"
type: decision
---

The full webhook flow was verified with a genuinely real event: created a real Linear ticket (AGE-5, TestIssue) in the AgentOps testing project via the Linear UI, assigned it, and a real webhook (real Linear-Signature/Linear-Delivery headers, User-Agent: Linear-Webhook) hit a locally-running agentops-heavy-api tunneled publicly via ngrok. Correctly verified and dispatched: scan_repo ran, a task was created with session_id linear-auto-kickoff-AGE-5. Two real design fixes landed during this live pass, not found by unit tests: (1) Linear's Webhook.secret field IS queryable via GraphQL (confirmed via live schema introspection against the real API) despite the docs page never selecting it in example queries, which had led to a wrong initial assumption that the secret could only be obtained via Linear's UI -- ensure_webhook_registered now returns the secret directly, making the whole setup flow fully automatic with zero manual copy-paste, and per-team (not one shared global secret, which would have been wrong for a multi-team config) -- the handler now tries each configured team's own secret against the raw body to determine which team a request is from, using the verified signature as the actual trust boundary rather than trusting the payload's own claimed teamId. (2) the webhook handler never logged a successful dispatch, only errors -- caught because a Monitor watching the server's own stdout log stayed completely silent through a real, successful dispatch, and the event was only visible via ngrok's separate HTTP traffic inspector. Fixed by adding a success-path log line.
