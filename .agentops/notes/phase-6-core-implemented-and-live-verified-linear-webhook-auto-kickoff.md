Module 9's core flow is built and live-verified against real Linear data (AgentOps testing project) and a real running agentops-heavy-api server, not just unit tests: assignee/team whitelist config (AutoKickoffConfig, JSON file via AGENTOPS_LINEAR_AUTO_KICKOFF_CONFIG, default off), idempotent startup webhook registration (agentops_linear::ensure_webhook_registered, checks existing webhooks by URL before creating), a new /webhooks/linear endpoint on agentops-heavy-api with real HMAC-SHA256 signature verification (constant-time via Mac::verify_slice) and 60-second replay-window timestamp checking, bounded in-memory delivery-id dedup, and dispatch (scan_repo with_embeddings + upsert_external_task with a linear-auto-kickoff-<identifier> session_id). Live-tested end to end: correct dispatch actually ran scan_repo and created a real task in a real target repo; wrong signature, missing signature, stale timestamp, and duplicate delivery id were all correctly rejected/deduped against a real running server, not mocked. Deliberately deferred from this first pass: doc-pull (sync-docs) integration -- that logic is CLI-only code today (agentops-cli::main::sync_docs, has an interactive-prompt fallback baked in), not a reusable library function, so wiring it into an unattended webhook receiver needs its own refactor first, flagged not silently skipped. Extensions 1-3 (configurable per-team status mapping, audience-tuned summaries, git branch push) remain design-only, each with open questions not yet resolved. Config storage note: agentops-manifest (the vault doc's original guess for where project-repo mapping might live) turned out to be the wrong home -- it's a local-machine-only ~/.agentops/manifest.json, but the webhook receiver runs as a hosted service, so a dedicated JSON config file loaded via env var was used instead.
