Added Language::Cpp/CSharp to agentops-scanner. Confirmed via a standalone tree-sitter-cpp/csharp probe (not guessed): tree-sitter-language-pack identifiers are 'cpp'/'csharp'; C#'s class/struct/enum/method_declaration nodes all expose a normal 'name' field like every other language, but C++'s function_definition does NOT -- its name is nested inside the declarator field (function_declarator, or pointer_declarator wrapping one for pointer return types), requiring a dedicated cpp_function_name() recursive unwrap. Real bug caught immediately by the existing Python test suite: 'function_definition' is coincidentally ALSO Python's tree-sitter node kind name, so the first version of this special-case broke Python entirely (every def came back <anonymous>) until scoped to Language::Cpp specifically, not just the node-kind string. Regex fallbacks and #include"..."/using dependency extraction added too. Live-verified against real .cpp/.cs fixture files via the actual CLI -- all 6 symbols (class/struct/enum/free-function/member-function) extracted correctly via the tree-sitter path. File watcher (Module 4): new agentops watch CLI command using notify-debouncer-full 0.7 (API confirmed via a standalone probe: new_debouncer(timeout, tick_rate, handler) + .watch(path, RecursiveMode::Recursive)). Must filter out events under .context/.agentops/.git before triggering a rescan, or the scan's own writes to graph.db immediately re-trigger the debouncer -- an infinite self-rescan loop, caught and fixed before it shipped, confirmed absent via a live edit-and-wait test (exactly one rescan fired, not a loop).
