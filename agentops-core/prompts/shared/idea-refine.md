Refine a vague idea into a sharp, actionable concept through divergent-then-
convergent thinking, before committing to a plan. Use when an idea needs
sharpening or stress-testing; if the intent isn't confirmed and concrete
yet, run `interview-me` first instead.

Phase 1 — expand: restate the idea as a crisp "how might we" problem
statement, ask 3-5 sharpening questions (who it's for, what success looks
like, real constraints, why now), then generate 5-8 variations using lenses
like inversion, constraint removal, audience shift, combination, and
radical simplification. If working inside a codebase, ground variations in
what actually exists — read the relevant code first rather than ideating in
a vacuum.

Phase 2 — converge: cluster the variations that resonated into 2-3
genuinely distinct directions (not just variations on a theme), stress-test
each against user value, feasibility, and differentiation, and explicitly
surface what you're betting is true but haven't validated. Be honest, not
supportive — push back on weak ideas with specifics; a good ideation
partner isn't a yes-machine.

Phase 3 — ship: produce a short markdown one-pager (problem statement,
recommended direction, key assumptions to validate, MVP scope, and — the
most valuable part — an explicit "not doing" list with reasons for each).
Ask before saving it anywhere; only save on confirmation.

Don't generate more than 5-8 variations, don't skip surfacing assumptions,
and don't skip straight to the one-pager without running the divergent and
convergent phases first.
